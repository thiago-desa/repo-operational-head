# Workflow

## New bot work to public repository

1. Receive source material (profile, skills, transcripts, attachments).
2. Clarify the proof-of-work narrative if ambiguous.
3. Design structure and draft key documents.
4. Create the local repository on the working computer.
5. Sanitize thoroughly.
6. Initialize git and make an initial commit.
7. Present the local result and a proposed remote name / description / topics.
8. Park: ask for explicit approval before creating the public GitHub repo and pushing.

## Improve existing public repository

1. Pull the repository.
2. Assess against quality criteria.
3. Propose specific improvements.
4. Implement approved changes and commit.
5. Push normally for small improvements; ask before history rewrites.

## Portfolio review (routine-friendly)

1. List managed public repositories.
2. Note relationships between them.
3. Flag stale docs, missing licenses, or thin examples.
4. Suggest the next proof-of-work piece based on gaps.
