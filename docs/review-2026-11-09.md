# Review findings and lessons (2026-11-09)

Portfolio review of six public proof-of-work repos and their matching Grok Bot templates, using `skills/repo-template-review.md`.

Repos: `citi-assist`, `computer-fix`, `conductor`, `repo-operational-head`, `website-betterment`, `open-weight-expert` on `github.com/thiago-desa`, plus public template links listed in each README.

## Cross-cutting before state

Shared strengths:

- Clean MIT layout with sanitized `agents/`, `skills/`, `docs/`, `examples/`
- Explicit approval gates in agent prose
- Fictional examples; import links present
- Honest "out of scope" notes on several agents

Shared high-leverage gaps (before this pass):

1. No `AGENTS.md` (agent-friendly entrypoint)
2. No golden-set evals (evaluation-driven development missing)
3. No `docs/failure-modes.md` (template usability / troubleshooting)
4. No hygiene CI (secrets/PII/em-dash/link sensors)
5. No `CONTRIBUTING.md`
6. Template contents thinner than repo claims on several bots (parity gap)

## What this pass changed in the repos

For every repo:

- Added `AGENTS.md`, `CONTRIBUTING.md`, `docs/failure-modes.md`, `evals/` golden set, `scripts/check.py`, `.github/workflows/checks.yml`
- Linked new paths from the README Key files table
- Kept existing Grok Bot import links

For `repo-operational-head` only:

- Added `skills/repo-template-review.md` and `graphs/review-graph.md`
- Wired review into the agent definition and workflow

## Generalized lessons (fold into skills)

1. **Ship sensors with the story.** A sanitized agent README without `AGENTS.md`, evals, failure modes, and CI is incomplete proof of work.
2. **Template parity is part of readiness.** If the repo documents five skills, the public template should pack them (or the README must clearly mark template scope).
3. **Golden sets beat adjectives.** "Approval gates" and "grounded drafts" need fictional Must/Must-not cases.
4. **Watchdog and offline paths are features.** Document what happens when the PC is offline, the channel is stale, or nothing is due.
5. **Provenance is a publish requirement for civic and on-device advice.** Dates and source URLs belong next to channel values and model shortlists.
6. **Review protocol should be recursive.** The bot that publishes repos must run the same checklist on itself.
7. **Import links are distribution.** Marketplace search may lag; README import links are the reliable discovery path.
8. **Em-dash and PII greps belong in CI**, not only in pre-commit memory.

## CI enablement note (same day)

The hygiene entrypoint `scripts/check.py` is live in every repo. A GitHub Actions workflow file is shipped as `scripts/github-workflow-checks.yml` instead of `.github/workflows/checks.yml` because the current GitHub OAuth token lacks the `workflow` scope and GitHub refused those pushes. To enable Actions: grant `workflow` scope (or use a PAT that has it), copy the file to `.github/workflows/checks.yml`, and push.
